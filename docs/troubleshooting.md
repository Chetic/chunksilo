# Troubleshooting

Part of [ChunkSilo](../README.md).

## Common issues

- **Index missing**: Run `chunksilo --build-index` (PyPI install) or `./venv/bin/chunksilo --build-index` (offline bundle).
- **Retrieval errors**: Check paths in your MCP client configuration. The MCP server's own log is `<storage_dir>/mcp.log`.
- **Offline mode**: PyPI installs default to `offline: false` (models auto-download). The offline bundle includes pre-downloaded models and sets `offline: true`. Set `retrieval.offline: true` in `config.yaml` to prevent network calls after initial model download.
- **Confluence Integration**: Included by default — set `confluence.url`, `confluence.username`, and `confluence.api_token` in `config.yaml`.
- **Jira Integration**: Included by default — set `jira.url`, `jira.username`, and `jira.api_token` in `config.yaml`. Optionally configure `jira.projects` to restrict search to specific project keys.
- **Custom CA Bundle**: Set `ssl.ca_bundle_path` in `config.yaml` for custom certificates.
- **Network mounts**: Unavailable directories are skipped with a warning; indexing continues with available directories. Files already indexed from a directory that could not be scanned — or individual files that could not be read — are **kept**, not treated as deleted, and the run reports how many (`N unseen (kept)`). Otherwise a mount that is briefly slow drops its whole tree from the index and the next run re-indexes it from scratch. The consequence is that content genuinely removed from a still-configured directory that has become unreachable stays in the index; to drop it, remove the directory from `indexing.directories` and rebuild.
- **Files that keep being re-indexed**: run `chunksilo --build-index --verbose` and look for `Reprocessing <path>:` — it names the reason (`content changed`, `revision status changed`). Files with no extractable text (an image-only `.docx`, for instance) are recorded as empty and are not retried until they change; files that failed to load are reported separately and *are* retried.
- **A file is not being indexed**: run `chunksilo --check-files <path>` — it names the exact reason (excluded by a glob pattern, no include pattern matched, pruned directory, superseded revision, review copy, disabled or unavailable directory) without re-indexing, and `chunksilo --check-files` alone reports a verdict for every file the scan sees (see [cli.md](cli.md#testing-the-file-filters---check-files)). By default only the newest revision of a document group is indexed, and review-comment copies never are; during a real build the scan summary counts them (`N superseded (skipped)`, `N review copies (skipped)`) and `--verbose` names each file. If the classification is wrong, adjust `indexing.versioning.review_copy_patterns` / `doc_id_patterns`, set `indexing.versioning.index_superseded: true` to keep old revisions searchable, or set `indexing.versioning.enabled: false` to turn revision handling off entirely (see [configuration.md](configuration.md)).
- **Results all come from one document**: `retrieval.max_chunks_per_doc` (default 2) caps how many chunks of one document appear; raise `retrieval.embed_top_k` to widen the pool it chooses from.
- **Legacy .doc files**: Requires LibreOffice to be installed for automatic conversion to .docx. If LibreOffice is not found, .doc files are skipped with a warning. Full heading extraction is supported. Conversion runs on a copy of the file in a private directory under `storage.storage_dir`, so nothing is ever written next to the original.
- **Old config options**: after upgrading from 2.x, a warning such as `'indexing.timeout' is no longer used and is ignored; use ...` means the file still sets a removed option; see the [upgrade notes](configuration.md#upgrading-from-2x).
- **HTTP transport**: `chunksilo-mcp --transport streamable-http` binds `127.0.0.1:8400` by default and authenticates nobody. If a remote client cannot connect, that is the loopback bind doing its job — put an authenticating reverse proxy in front and point `server.host` at the address the proxy uses, rather than exposing the port directly.
